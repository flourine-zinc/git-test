# Todo List Project Rules

## Project Overview

This is a Todo List application. The goal is to create a clean, maintainable, and user-friendly task management app.

## Development Rules

### Code Style

- Write clean and readable code.
- Prefer simple solutions over unnecessary complexity.
- Use meaningful variable and function names.
- Keep functions small and focused.
- Add comments only when the logic is not obvious.

### Before Making Changes

- Analyze the existing project structure first.
- Explain what files will be changed and why before editing.
- Do not modify unrelated files.
- Ask before making major architectural changes.

### Frontend Rules

- Build reusable components instead of repeating code.
- Keep UI components separate from business logic.
- Maintain consistent naming conventions.
- Keep the UI responsive for different screen sizes.

### Todo Features

The application should support:

- Creating new tasks.
- Displaying a list of tasks.
- Marking tasks as completed.
- Editing existing tasks.
- Deleting tasks.
- Filtering tasks (All, Active, Completed).
- Persisting tasks using local storage or a database when required.

### Data Handling

- Keep data structures simple and predictable.
- Use proper state management patterns.
- Avoid unnecessary global state.
- Validate user input before saving data.

### Git Rules

- Make small, meaningful commits.
- Do not commit temporary files.
- Do not remove existing functionality without confirmation.

### Quality Rules

Before finishing a task:

- Check for errors.
- Verify that existing features still work.
- Explain what was changed.
- Mention any possible improvements.
